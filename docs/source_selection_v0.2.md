# 模型参数来源取舍说明（v0.2）

日期：2026-11-08

配套参数表：`data/model_parameter_priors_v0.2.csv`

本版依据新增的 `05_田块级实测数据外部来源清单_v0.2.csv` 和 `06_E20核验_间作水肥年份混杂_v0.1.md` 更新。v0.1 文件保留，不再作为模型输入。

## 1. 当前结论

最终采用 4 条来源，形成 21 条参数记录：

| 来源 | 采用内容 | 参数 ID |
|---|---|---|
| E01 | 河南漯河夏玉米孕穗期排水延迟和追氮的产量效应 | P001—P004 |
| E02 | 台风后早期和晚期施药对南方锈病的防效与增产效应 | P005—P012 |
| E04 | 不同生育期、不同淹水历时下的产量损失锚点 | P013—P018 |
| E14 | 河南“7·20”区域评估中的连续淹水 3 天、5 天、≥7 天分级 | P019—P021 |

E20 已从参数表移除。它仍可作为病害严重度数量级和试验设计参考，但不能用于拟合严重度—产量斜率。

## 2. 新增核验带来的修正

### E20 撤回内容

原 v0.1 参数 P019 使用 E20 的未调整斜率 `-0.298687 t/ha/严重度单位`，该参数不再有效。

新增核验证明：

- `severity` 表有 543 条记录，但去重后只有 494 个有效独立单元；
- `yield and harvest index` 只有 36 条年×种植制度×区组均值，缺少 site、experiment、treatment 和日期键；
- 产量表与严重度表不能在小区域组级别连接；
- 未调整斜率看似显著，但加入年份和种植制度后不显著，单作子集甚至翻转符号；
- 因此无法从 E20 识别“病情→产量”的可靠斜率。

保留用途只有三项：

- 判断锈病严重度的常见数量级；
- 参考随机区组、多年和单作对照的设计；
- 后续向作者索取处理级产量和调查日期。

### E14 新增用途

E14 的公开摘要可以确认：

- 连续淹水 3 天被归为中等受淹；
- 连续淹水 5 天被归为严重受淹；
- 连续淹水至少 7 天被归为绝收区域。

摘要没有公开“淹水时长—减产率”和“追肥补偿”的具体公式或系数，因此本版只使用分级阈值，不生成精确减产曲线。

## 3. 参数使用边界

### E01

已核对公开摘要，采用排水延迟 3 天和追氮的产量效应。它是产量效应，不是病害防效，也不能单独证明排水降低南方锈病风险。

### E02

已核对公开摘要中的防效和增产率，但当前可访问摘要没有给出“台风后 2 天”和“台风后 21 天”的原文依据。

因此第一版：

- 可以比较“早期”和“晚期”；
- 不得默认显示 48 小时、2 天或 21 天的精确窗口；
- 精确天数必须等全文或作者确认。

### E04

采用中国农业科学院农田灌溉研究所公开新闻中明确列出的数值锚点。参数表保留“小于 25%”“接近 50%”“超过 20%”的原始语义，不把它们伪造成精确平均值。

在 v0.3 页面中，E04 只用于生育期×淹水历时的粗略“处置关注”分级：

- P013：`time_value=4` 用于V3/V6/VT不超过4天的状态文字分支；`value_high=25` 是解释性减产上界，不进入风险分数；
- P016：V6 超过6天后的损失加速锚点；
- P014、P015、P017、P018：V3、V6、VT、R3 的10天结果锚点。

这些参数不生成逐日减产率，也不用于病害概率、排水日期或施药窗口。

### E14

3 天、5 天、7 天是区域遥感评估中的受淹程度分级，不是三组受控田间试验。它们只能用于粗粒度的风险分层和情景边界，不能替代 E04 的生育期×淹水历时参数。

v0.3 进一步确认 E14 只描述区域遥感像元。田块明水天数与区域像元受淹天数不是同一数据对象；在没有独立像元分类结果时，页面显示“暂无独立遥感像元数据”，P019—P021 不进入本次田块执行路径。

## 5. 进入核心计算前仍然缺少什么

必须保留以下缺口，不用伪造数值填补：

1. E02 的精确“早期/晚期”施药天数；
2. E12 的防治成本与效益数值；
3. 病情严重度到产量损失的可靠局部关系；
4. 本地受灾田与未受灾对照田数据。

这些缺口不会阻止第一版情景决策核心开发，但会限制结果只能显示为“风险区间 + 证据等级 + 待校准”，不能显示为精确预测。
