# v0.6 案例包与本地数据库

日期：2026-11-13

## 目标

把河南玉米从“写死在引擎里的案例”改为“版本化案例包”，并让田块CSV和风险计算在单用户本机环境中持久保存。

本版仍只覆盖玉米洪涝—病害场景，不包含其他作物、云数据库、登录或多人权限。

## 案例包

默认案例目录：

```text
case_packs/henan_maize_2026/
```

第二案例目录：

```text
case_packs/us_corn_belt_cscap_2011_2015/
```

第二案例使用 `monitoring_only` 模式，详见 `docs/us_corn_belt_case_v0.1.md`。

其中 `case.json` 保存：

- 国家、地区、作物和版本；
- 生育期、病害、品种和界面标签；
- 情景预设；
- 参数与规则文件路径；
- 病害环境模型与防治策略；
- 参数和规则ID映射；
- 模型限制文本。

参数、规则和数据缺口表由案例目录独占。引擎不再直接读取固定河南文件，也不再在代码中保存河南品种白名单。

案例包可通过环境变量选择：

```powershell
$env:FLOOD_APP_CASE_ID="henan_maize_2026"
```

## 数据结构

新模板为 `data/field_observation_template_v0.6.csv`，在原模板上增加：

- `case_id`
- `region_code`
- `country_code`
- `admin_level_1`
- `admin_level_2`
- `crop_code`
- `yield_kg_ha`
- `intervention_cost_per_ha`
- `currency_code`

原有亩和人民币字段保留，避免破坏历史文件。新数据优先填写统一单位字段。

## SQLite

默认数据库：

```text
data/app.db
```

表与职责：

| 表 | 职责 |
|---|---|
| `import_batches` | 记录文件哈希、原始CSV、导入时间和错误摘要 |
| `field_observations` | 一行对应一个田块观测及其计算结果 |
| `assessment_runs` | 保存唯一风险计算的输入、结果和案例版本 |

相同CSV内容按SHA256去重。当前不提供删除和修改数据库记录的界面，避免误删研究数据。

## 安全边界

- 当前只有本机单用户，没有登录系统；
- SQLite文件是本机数据，不能直接暴露给外部用户；
- 免费数据库或本地磁盘都不替代备份；
- 接入云端前必须增加账号、角色、审计和传输加密；
- 公开数据、遥感推算、农户回忆和实测记录继续使用不同证据等级。
